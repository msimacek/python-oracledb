.. _exception:

*******************
Handling Exceptions
*******************

All exceptions raised by python-oracledb are inherited from :attr:`oracledb.Error`.
See :ref:`Exceptions <exceptions>` for more details on the various exceptions
defined by python-oracledb. See the exception handling section in the
:ref:`API manual <exchandling>` for more details on the information available
when an exception is raised.

.. need Chris's confirmation on the below info

The exception types in the python-oracledb driver are similar to cx_Oracle 8.3
and follow this approach:

  - 1000-1999: exceptions.InterfaceError
  - 2000-2999: exceptions.ProgrammingError
  - 3000-3999: exceptions.NotSupportedError
  - 4000-4999: exceptions.DatabaseError
  - 5000-5999: exceptions.InternalError
  - 6000-6999: exceptions.OperationalError

.. note::

   Some of the errors like DPY-6001 are OperationalError which is a subclass
   of DatabaseError. These exceptions can be caught in the same way as in
   cx_Oracle 8.3.

Applications can catch exceptions as needed. For example, when trying to add a
customer that already exists in the database, the following could be used
to catch the exception:

.. code-block:: python

    try:
        cursor.execute("insert into customer values (101, 'Customer A')")
    except oracledb.IntegrityError:
        print("Customer ID already exists")
    else:
        print("Customer added")


If information about the exception needs to be processed instead, the following
code can be used:

.. code-block:: python

    try:
        cursor.execute("insert into customer values (101, 'Customer A')")
    except oracledb.IntegrityError as e:
        error_obj, = e.args
        print("Customer ID already exists")
        print("Error Code:", error_obj.code)
        print("Error Full Code:", error_obj.full_code)
        print("Error Message:", error_obj.message)
    else:
        print("Customer added")

.. _errorhandling:

Error Handling
===============

The Thin and Thick modes of python-oracledb handle errors differently.

Error Message Prefixes
----------------------

The python-oracledb Thin and the Thick modes return error messages generated
by the database unchanged. On the server side, Oracle Database and Oracle Net
Services return error messages with the prefix "ORA".

The python-oracledb Thin mode generates all error messages with the prefix "DPY".

In python-oracledb Thick mode, the error messages generated by the client differ
as shown below.
- Oracle Call Interface (OCI) generates error messages with the prefix "ORA"
- `ODPI-C <https://oracle.github.io/odpi/>`_  generates error messages with the
prefix "DPI"
- The python-oracledb driver generates error messages with the prefix "DPY"

Error Messages
--------------

In python-oracledb Thick mode, error messages generated by OCI and ODPI-C are
returned unchanged from cx_Oracle 8.3 with the following exception:

``ConnectionPool.acquire()``: ORA errors will be mapped to DPY errors. For example::

  DPY-nnnn: timed out waiting for pool to have free connections available or
  create new connections

will replace the old cx_Oracle 8.3 error::

  ORA-24459: OCISessionGet() timed out waiting for pool to create new
  connections

Some of the client-side messages vary between the python-oracledb Thick and
Thin modes and are listed below:

* Binding: When binding is not done properly, the error messages which are
  generated differ in the python-oracledb Thin and Thick modes.
  The python-oracledb Thick mode generates these exceptions::

    ORA-01008: not all variables bound
    ORA-01036: illegal variable name/number

  In contrast, the python-oracledb Thin mode generates these exceptions::

    DPY-4010: a bind variable replacement value for placeholder "1" was not provided
    DPY-4008: no placeholder named "x" was found in the SQL text
    DPY-4009: 2 positional bind(s) required but only 1 positional bind(s) provided

* Connection Pooling: The python-oracledb Thin mode pool is not based on the Oracle
  Call Interface (OCI) Session Pool and has its own DPY messages.

* Connection and Network messages: The python-oracledb Thin mode returns connection
  and network messages directly from the Python layers. The traditional Oracle
  connection errors with prefix ``ORA`` is not shown. For example, the scenarios
  detailed below show how the connection and network error messages differ for the
  python-oracledb Thick and Thin modes on a macOS:

  * Scenario 1: The given hostname does not have a listener running.

    Thick Error::

      oracledb.exceptions.DatabaseError: ORA-12541: TNS:no listener

    Thin Error::

      ConnectionRefusedError: [Errno 61] Connection refused

  * Scenario 2: dsn="xyz" and there is no tnsnames.ora file.

    Thick Error::

      oracledb.exceptions.DatabaseError: ORA-12154: TNS:could not resolve the connect identifier specified

    Thin Error::

      oracledb.exceptions.DatabaseError: DPY-4000: cannot connect to database. Unable to find "{name}" in file_name}

  * Scenario 3: dsn="localhost/xyz" where there is a listener on the host

    Thick Error::

      oracledb.exceptions.DatabaseError: ORA-12514: TNS:listener does not currently know of service requested in connect descriptor

    Thin Error::

      oracledb.exceptions.OperationalError: DPY-6001: cannot connect to database.
      Service "{service_name}" is not registered with the listener at host "{host}" port {port}.
      (Similar to ORA-12514)

Dead Connection Detection Messages
----------------------------------

Your application code which detects dead connections will need to check for new error
numbers. The scenarios below show the various dead connection detection messages
that are displayed for the python-oracledb Thin and Thick modes and the cx_Oracle 8.3 driver.

* Scenario 1: An already closed or dead connection was attempted to be used.

  Thin Error::

    DPY-1001: not connected to database

  Thick Error::

    DPY-1001: not connected to database

  cx_Oracle Error::

    not connected

* Scenario 2: A connection error occurred while using the connection. For example, the
  database side of the connection was terminated.

  Thin Error::

    DPY-4011: the database or network closed the connection
    DPI-1080: connection was closed by ORA-%d

  Thick Error::

    DPY-4011: the database or network closed the connection
    DPI-1080: not connected

  cx_Oracle Error::

    DPI-1080: connection was closed by ORA-%d

* Scenario 3: Using connection.call_timeout

  Thin Error::

    DPY-4024: call timeout of {timeout} ms exceeded

  Thick Error::

    DPY-4024: call timeout of {timeout} ms exceeded
    DPI-1067: call timeout of %u ms exceeded with ORA-%d

  cx_Oracle::

    DPI-1067: call timeout of %u ms exceeded with ORA-%d
